# 思政报告：在校园评教与模拟激励平台中践行诚信、责任与规范

> 成员：张善言（24320218）｜课程实践：《学林街之狼》项目
> 本文结合项目真实设计（匿名评教防刷分、虚拟标的免责边界、多人合流协作、AI 协作人机分工），谈课程实践中对诚信、责任、规则与协作的体会。

## 一、引言

本次课程要求以小组为单位，从立项、技术方案到编码交付完成一个完整的校园教学评价与模拟投资激励平台前端原型。开发之外，项目本身处处涉及价值观选择：如何让“匿名评价”既保护表达又不伤害他人、如何让“模拟激励”不误导为真实投资、如何在多人并行开发中守住质量底线。这些选择构成了本报告的思政主线：**用制度设计守护诚信，用边界声明守住责任，用规范协作锤炼品格。**

## 二、匿名不是免责：评价机制里的诚信与责任

项目核心功能是“到课签到—匿名评教—聚合入市”。设计上刻意做了三道“闸门”：只有完成签到的学生才能评、同节课不可重复评、文字内容进入可审核流程并支持驳回/降权。这让我理解了一个朴素的道理：**匿名保护的是表达权利，而不是表达责任。**

一个匿名评价系统若没有防刷分与审核机制，个别恶意差评就能淹没认真教学的声音。代码里的 `clampRating`、近 5 讲窗口聚合、指数平滑，表面上是在“算平均数”，本质上是在用工程手段维护一种公平——让每一条评价都真实、克制、可追溯地发生。课程教会我：技术方案从来不是价值中立的，**写下每一行防滥用的逻辑，就是在写下我们对诚信的选择**。

## 三、虚拟与真实的边界：规则意识与风险提示

项目把课程评价包装成“股票行情”，用虚拟积分激励参与。立项书、演示开场和 README 反复声明：所有“股票”“交易”“资产”均为虚构，不涉及真实证券、支付或投资建议。起初我以为是多余的免责声明，真正实现“收盘结算—次日开盘”链路后才意识到，**模拟和真实的边界如果不讲清楚，轻松会滑向误导**。

在写评分聚合与因子公式时我始终提醒自己：我们造的是一个“教学玩具”，但它演示的纪律感是真实的——庄重对待规则、清晰划出边界、主动提示风险，这是任何面向公众的系统都必须有的职业底线。

## 四、多人合流里的担当与规范

五人并行开发、定期向 `main` 合流，是本课程最有“真实职场感”的经历。我们经历了分支冲突、页面被重构换版、合并后整站白屏等事故。排查“白屏”时，根因竟然是一个 **build 能通过、运行才报错的缺失 import**——这给我上了深刻一课：**“构建通过”不等于“做对了”**。

从那以后我们养成了三件事：功能分支 + Pull Request、改共享类型前先同步组长、把每次验证以“命令＋输出＋提交号”登记入库。这不是流程主义，而是对队友负责：我的一个疏忽会变成五个人的返工。**把简单的事按规范做、把发现的问题说清楚、把遗留问题交接明白**，是比代码更重要的协作品格。

## 五、AI 协作中的主体性与人的责任

本次开发大量使用了 AI 辅助编码。我的体会是：AI 极大地提升了产出效率，但**方向判断、规则决策与验收责任始终在人**。例如“是否引入每日任务跨天重置”“匿名评价该不该允许校外用户”“改一处常量还是全链路收口”，这些取舍都由人拍板；AI 生成的代码也只有在人工逐条回归、类型检查与端到端冒烟后才能相信。工具越是强大，越考验使用者的判断力与责任感——**人在回路（human-in-the-loop）不是效率损失，而是技术伦理的底线**。

## 六、结语

六周的项目实践让我看到：一次课程设计可以同时是技术训练与品格训练。我们用聚合窗口守护评价的公平，用边界声明守住产品的诚实，用合流规范磨炼协作的责任，用 AI 协作练习做技术的主人而非工具的附庸。这些体会将伴随我进入更真实的学习与工作场景：**做一个守诚信、有边界、能担当、善协作的人**，先于做一个会写代码的人。
