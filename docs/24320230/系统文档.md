## 0. 项目定位与边界

“学林街之狼”以行情看板的交互形式组织课程、教师与评价信息，通过模拟交易、任务与排行榜提升课程参与度，并为教学管理者提供评价审核与趋势查看入口。**本系统中的“股票”“交易”“资产”“收益”均为虚构标的与虚拟积分，仅用于教学互动演示，不提供任何真实证券、支付或投资建议**；本期末交付的是可运行、可构建的前端原型，不含生产级后端与持久化。

## 2. 总体架构

```mermaid
flowchart TB
  subgraph UI[展示层 views + components]
    M[行情/详情] --> NAV[Navbar 导航]
    T[交易/个人中心]
    E[课程/签到/评教]
    K[任务/排行]
    A[管理端]
  end
  subgraph ST[状态层 stores]
    S1[market] S2[trade] S3[evaluation] S4[task] S5[user] S6[ranking]
  end
  subgraph RULE[规则真源 src/rules.ts 纯函数]
  end
  subgraph DATA[数据源 mock / api 契约]
  end
  UI --> ST
  ST --> RULE
  ST --> DATA
```

分层职责：`views` 只负责展示与交互；`stores` 统一读写业务状态并消费规则；`rules.ts` 是易变规则的唯一实现点；`mock/` 提供初始数据，未来由 API 层替换而页面不改。

## 5. 数据与状态设计

### 5.1 数据源策略

原型阶段所有业务数据由 Pinia store 初始化并保存在内存中，初始值来自 `mock/initialData.ts`（含行情、K 线、评价、课程、任务、教师档案等）。**刷新页面后恢复初始状态**是本阶段的明确行为而非缺陷。为兼容演示，每日任务只在确实跨天时重置（`shouldResetDaily`），同日刷新保留演示进度。

### 5.2 Store 职责与跨店联动

| Store | 职责 | 向外提供 |
| --- | --- | --- |
| market | 行情列表、K 线缓存、宏观因子、次日预测 | filtered/selected 标的、projection |
| trade | 订单、持仓批次、可卖汇总、成交流水 | positions、可用股数、feePool |
| evaluation | 课程会话、签到记录、评价与审核状态 | 可公开评价流、last5Avg |
| task | 任务进度、领取状态、跨天结算 | claim 结果、进度视图 |
| user | 角色、余额、月卡、账本 | 资产派生所需原始值 |
| ranking | 排行派生（只读消费） | 排行列表 |

联动示例：评教提交 → evaluation 更新评价流并回写标的 `rating/last5Avg` → market 趋势变化 → task 推进 `COURSE_EVALUATION` → 领奖写 user 账本。所有金额为整数学币。

### 5.3 共享类型要点

`types/index.ts` 维护 `UserRole`、`TradeSide`、`MarketTab`、`SortOrder`、`AuditStatus`、`ActionResult`、`NextDayProjection` 等联合类型与接口，约束跨模块字段口径。新增字段时同步更新 mock 初始数据与 store 初始化，避免“类型写了、数据没给”的运行时空值。

## 6. 业务规则规格（前后端共同基准）

> 规则以 `src/rules.ts` 为唯一实现真源，语义对前后端同等有效；后端实现时须镜像本节并复刻 `tests/rules.test.ts` 用例。

### 6.1 评价与任务

- 评分约束 `1 ≤ rating ≤ 5`（`clampRating`）。
- 聚合窗口 5：最近 5 条前插截断；首条直接成为 last5Avg；EMA 平滑（新分权重 0.05）。
- 评分因子：`E = 0.02 × (last5Avg − 3.0) / 2`，正值抬升标的、负值压低。
- 签到奖励 100、评教奖励 80；重复签到/重复评教幂等拒绝。
- 评价默认匿名：`anonymous !== false` 时展示名为“校内匿名同学”。
- 任务进度只增不减并封顶 target；领取条件为 `!isClaimed && current >= target`。
- 每日任务惰性跨天结算；`DAILY_LOGIN` 当日自动达成（仅当未领取且未达标）。

### 6.2 交易与账本

- 手续费 `TRADE_FEE_RATE = 0.1%`；月卡 5 折后 0.05%；`FEE_POOL_RETAIN_RATIO = 50%` 手续费留存奖池。
- 应付 = 成交额 + 手续费；净回笼 = 成交额 − 手续费。
- 仓位风控：单标的市值 ≤ 总资产 30%；恰为 30% 不触发、超出触发；最大可加仓量整股截断、预算不足为 0。
- 持仓按批次记账，卖出仅能扣可售批次并按 FIFO 顺序扣减；摊薄成本按持仓金额加权。
- 审核状态集 `[APPROVED, DOWNWEIGHTED, REJECTED]`；公开口径 `isReviewPublic` 仅 APPROVED。

## 7. 模块设计说明（维护索引）

| 模块 | 页面与组件 | store | 设计要点 | 修改前注意 |
| --- | --- | --- | --- | --- |
| 行情与详情 | MarketView / StockDetailView / KLineChart / RatingTrendChart | market + trade + evaluation + user | 视图态不入 store；K 线用 klineCache 避免重复生成 | echarts 按需注册清单需同步补充 |
| 模拟交易 | TradeView / ProfileView | trade + user | 规则全部走 rules.ts；T+1 批次账本 | 不得在视图内联手续费/仓位计算 |
| 课程评教 | MyCoursesView / EvaluationView | evaluation + task + user | 签到是评教前置；提交后聚合回写行情 | 幂等与匿名脱敏语义不可破坏 |
| 任务激励 | TaskView | task + user | 跨天结算惰性化；领取即写账本 | 日期格式统一 YYYY-MM-DD |
| 排行与管理 | RankingView / AdminView | ranking + market + evaluation | 审核三态与公开口径一致 | 驳回/降权需即时从对外列表下架 |
| 全局集成 | App / Navbar / router | user | 路由元信息标题；角色切换模拟 | 共享文件，修改前同步 |

## 8. 测试与质量

- **单元测试**：`tests/rules.test.ts` 覆盖常量、评分聚合、因子公式、每日结算、领奖资格、进度推进、费率月卡、仓位风控、摊薄、T+1 FIFO、审核状态集与公开口径，共 20 项（`npm run test` 全绿）。
- **构建门禁**：合流与定版前必须 `npm run build`，超限告警不允许带出。
- **人工验收**：按演示主流程逐页浏览器走通；每个“已关闭/已修复”声明须能指向台账条目与验证记录编号。
