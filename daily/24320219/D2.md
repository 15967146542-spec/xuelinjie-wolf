二、实际进展与成果

1. Git 与 Gitee 基础操作学习
在开始代码上传前，我先系统地复习并实操了 Git 的基本命令，确保基础操作熟练无误。重点练习了本地仓库的初始化、工作区文件的添加与提交、以及远程仓库的关联与推送。同时，针对团队协作需要，专门学习了 Gitee 平台的远程仓库创建流程，并对比了 HTTPS 与 SSH 两种推送方式的配置区别，最终选用了 HTTPS 方式以便于后续在不同设备上的快速克隆。

2. 项目仓库创建与本地代码初始化
我在 Gitee 上成功创建了名为 xuelinjie-wolf 的远程仓库，并将其设置为私有权限，保障代码安全。随后，在本地项目根目录执行 git init 完成了仓库初始化。

关键操作：在首次推送时，遇到了因 node_modules 目录过大导致的推送缓慢问题。我通过创建 .gitignore 文件，并在其中添加 node_modules/、dist/ 等构建产物目录，有效减小了仓库体积。随后执行了以下命令从缓存中移除该目录并完成忽略配置：

bash
git rm -r --cached node_modules
git add .gitignore
git commit -m "Add .gitignore to exclude node_modules"
首次推送：在关联远程地址后，使用 git push origin main 成功将主分支代码推送至远程仓库。

3. 分支管理实践
为遵循规范的开发流程，我创建了 feature/ranking 分支用于专门开发排行榜功能。操作命令为 git checkout -b feature/ranking，并在此分支上完成了今日的部分代码提交。此举确保了主分支的稳定性，为后续并行开发管理端功能预留了干净的基线。

三、遇到的问题与解决方案

问题1：Gitee 仓库创建后首次推送权限报错

现象：执行 git push 时提示权限不足或远程地址无效。

解决：确认仓库地址无误后，我使用 git remote add origin https://gitee.com/username/xuelinjie-wolf.git 重新设置了远程地址。同时，由于 Gitee 在 2025 年后加强了安全校验，我通过在推送弹窗中输入个人访问令牌（Token）而非登录密码，成功解决了身份验证问题。

问题2：分支合并时的冲突预演

现象：虽然今日未涉及多人协作，但我在本地模拟了主分支与特性分支的合并冲突，为日后团队协作做准备。

解决：学习了 git pull origin main 同步主分支最新代码，并使用 git merge feature/ranking 进行本地合并。通过手动编辑冲突文件并提交，提前熟悉了解决冲突的标准流程。
