## 一、模块概述与个人职责

“学林街之狼”是校园教学评价与模拟投资激励平台的前端原型，基于 Vue 3、TypeScript、Vite、Pinia、Vue Router 与 Element Plus 构建，全部数据为虚构标的与虚拟积分。我负责排行榜与管理端模块：在立项阶段与组长、队友共同确认模块边界，绘制页面原型并定义状态结构；在技术方案阶段确定榜单数据口径、名人堂展示规则、龙虎榜数据源与称号规则、管理端审核与结算交互；在实施阶段完成 `src/stores/ranking.ts`、`src/views/RankingView.vue`、`src/views/AdminView.vue`、共享类型 `src/types/index.ts` 中相关接口以及身份权限配置，并配合联调、构建与演示。

## 二、需求分析与模块划分

排行榜面向学生、校外用户与管理端角色，需要把参与行为转化为可见、可比较的成长反馈。围绕这一目标，将模块拆分为四个榜单与一个荣誉区：校内总资产榜（仅展示校内学生）、校外总资产榜、每日收益率榜、龙虎风云榜（按主力净流入对全量老师标的表现排序），以及“每周日 18:00 结算、称号有效期 7 天”的周度荣誉称号名人堂。管理端面向教学管理者，需要评价审核队列（通过/驳回/降权）、宏观因子配置与模拟收盘结算三类能力，并与交易、行情模块联动。

## 三、总体设计与关键技术方案

### 3.1 类型与状态设计

在 `src/types/index.ts` 中定义榜单基础类型：`RankingUser`（排名、昵称、头像、身份、总资产、日/周收益率、称号等）、`DragonTigerItem`（代码、名称、教师、买/卖/净流入额、称号与高亮类型 TOP/BOTTOM）、`WeeklyTitle`（周称号及持有人、有效期）。状态集中在 `src/stores/ranking.ts`，以计算属性派生各榜单：`campusRankings` 过滤学生并按总资产降序后重排名次，`externalRankings`、`dailyProfitRankings` 同理；`liveRankings` 将当前用户实时总资产从交易 store 同步进榜单，保证“我”的资产变化即时反映排名，避免手工维护两份数据。

### 3.2 名人堂前三展示与结算倒计时

前三名从总榜抽离为独立卡片，采用“冠军居中、亚军在左、季军在右”的领奖台式布局。关键设计是：数据顺序保持不变，仅用 CSS `order` 调整视觉排列，使排名计算与展示层解耦；冠军头像放大并配金边、称号与红色加粗总资产，突出荣誉感。同步设计“每周日 18:00 结算”的倒计时与称号有效期提示，结算时刻取下一个周日 18:00，跨周边界返回正值，避免出现负数倒计时。

### 3.3 龙虎风云榜

龙虎榜从“写死几条 Mock”改为读取行情 store 中的全量老师标的（行情未就绪时回退同源 Mock），按主力净流入降序排序，仅对最好两支授予“多头总龙头、多头人气王”（金色高亮）、最差两支授予“空头总龙头、恐慌出逃王”（蓝色高亮），其余行不授称号，避免视觉噪声；页面加入分页，每页 20 条，并在挂载时幂等调用 `marketStore.bootstrapMarket()` 确保数据就绪。买卖盘金额由成交额与主力净流入推演（买入＋卖出＝成交额，买入－卖出＝净流入），并增加“数据不足四条不授称号”的边界防护；每行提供“详情”跳转，通过 `selectStock(code)` 进入 `/stock/:code`。

### 3.4 管理端

`AdminView.vue` 采用“宏观参数面板＋审核队列”双栏布局：左侧调整宏观指数（0.5–2.0、步长 0.05）、公告标题与描述，保存后调用 `marketStore.updateMacroFactor` 全局广播；右侧为评教审核队列，支持通过、驳回、降权三种处置，调用 `evaluationStore.moderateEvaluation` 更新状态；另提供模拟收盘清算入口（15:30 引擎调度），将当期评教与宏观因子聚合结算并解锁 T+1 持仓，作为规则验证与演示入口。

### 3.5 身份权限与路由

为配合榜单与管理端可见性，参与设计了 STUDENT/EXTERNAL/TEACHER/ADMIN 四类身份及功能权限位：`user.ts` 中以 `canUse` 定义各身份的可用功能（如校外用户可看榜不可评教，教师只读），`router/index.ts` 为 `/rankings`、`/admin` 等路由配置 `roles` 元信息并在前置守卫中拦截越权跳转，`Navbar.vue` 按身份隐藏入口，避免“只藏入口、URL 仍可直访”的漏洞。

## 四、实施过程中解决的关键问题

1. 前三名布局与排序冲突：若直接改数组顺序会破坏排名计算，改用 CSS `order` 控制“2-1-3”视觉排列，数据与展示解耦。
2. 倒计时跨周边界：周日 18:00 后出现负值，梳理取“下一结算时刻”的逻辑，增加跨周判断。
3. 龙虎榜空数据与分页空白：行情 store 异步化后未触发加载导致列表为空，页面挂载时幂等调用 `bootstrapMarket()`；称号授予增加条数判断，不足四条不授称号。
4. 权限粒度不足：仅隐藏入口仍可 URL 直访，补充路由级身份校验并强制重定向。
5. 记录与提交不一致：核对日报、提交号与 PR（如 `ranking.ts` 提交与 PR !47），修正路径写错与“未提交却已记录”的表述，保证文档可追溯。

## 五、质量验证与协作

功能完成后的验证包括：`npm run build` 生产构建通过；本地启动后按“进入榜单→名人堂→切榜→龙虎榜翻页→详情跳转→管理端审核/结算”的路径人工走查，覆盖空数据、边界条数与异步加载场景；改动共享类型与 Mock 前先同步组长，功能分支提交并发起 Pull Request 合入主分支，按天维护日报与提示词记录供追溯。

## 六、总结与展望

本模块完成了从“静态写死的榜单”到“全量数据驱动的多榜单”，从“展示与计算耦合”到“分层解耦、单一数据源”，从“只藏入口”到“路由级权限收口”的收敛。后续方向：将排行榜与管理端接入真实后端 API 与持久化；把称号授予、结算倒计时等边界规则固化为自动化测试；完善名人堂与管理端在移动端的响应式适配；对“数据不足”等极端输入补充更细的降级策略。
