# 《学林街之狼》设计报告

## 一、项目概述与个人职责

“学林街之狼”是校园教学评价与模拟投资激励平台前端原型：以行情看板的交互形式组织课程、教师与评价信息，通过任务、虚拟积分与排行榜提升参与度，并为教学管理提供评价审核与趋势查看入口。项目采用 Vue 3 + TypeScript + Vite + Pinia + Vue Router + Element Plus + ECharts，分模块并行开发后合流。

个人负责**签到评教、任务激励与评教趋势**，交付物为评价页、任务页、评价与任务 store、趋势图组件；共享类型、初始数据与路由改动遵循先同步后修改的约定。

## 二、总体技术方案

- **分层**：views（页面）→ stores（业务状态）→ mock/数据与 types（共享模型），页面只负责展示与交互。
- **规则单一来源**：奖励金额、聚合窗口、指数平滑权重、因子公式等集中为 `src/rules.ts` 纯函数模块，store 只做编排；视图文案以常量插值引用，避免规则与展示漂移。
- **数据流示例**：签到/评教 → `evaluationStore` 校验 → 更新 `evaluations` 并回写 `marketStore` 聚合字段 → 发放奖励并推进任务进度；管理端收盘结算时评分均值进入次日价格因子（E=α×(R̄−3)/2）。

## 三、本模块关键设计

### 3.1 签到评教
- 到课签到（幂等：重复签到不重复发奖）、评价前置校验（未签到不可评、同课不可重复评、EXTERNAL 角色兜底校验在 store 层）。
- 匿名评价入库默认脱敏为“校内匿名同学”，与真实身份边界明确。

### 3.2 任务激励
- **行为-任务解耦**：业务动作以 trigger（CLASS_SIGNIN / COURSE_EVALUATION / DAILY_LOGIN / MAKE_TRADE）驱动任务进度，任务侧按事件匹配自身 DAILY 任务，避免双方硬耦合任务 id。
- **每日结算**：跨天判定/归零/登录任务自动达成抽为 rules 纯函数，在应用加载与每次任务写操作前幂等执行（修复页面跨天不刷新时旧任务仍可操作、登录任务无法达成的断链）。

### 3.3 评教趋势
- `RatingTrendChart` 按需引入 ECharts，窗口大小与中性线参数化：调整聚合窗口只需改 `rules.ts`，聚合、图表 x 轴、tooltip 与文案自动跟随。
- 评教页“次日影响推演”卡片数据驱动：读取当前课程关联标的的真实评分均值与评价数，实时展示预计因子收益与看多/看空方向。

### 3.4 工程质量
- **类型检查**：补 vue-tsc 验证（typescript@5 配对），修复构建无法拦截的“未定义名称”类错误（含 `TaskItem.type` 缺 `GROWTH` 等历史类型不一致）。
- **单元测试**：`tests/rules.test.ts`（node:test、零依赖）覆盖奖励常量、评分聚合、因子公式与每日结算；后续由组长扩展交易/审核规则用例至 20（验证记录 V7/V8）。
- **API 契约先行**：`src/api/evaluationTaskApi.ts` + 契约文档定义签到/评教/任务/领奖/评价查询的请求响应类型，未接入后端前抛错防误用，store 为预留替换点。
- **回归与自动化冒烟**：使用 playwright-core 驱动系统浏览器做 headless 端到端回归（签到→任务进度→领奖→评教→再领奖→流水闭环通过），并全页面扫描运行时错误。

## 四、联调中发现并修复的回归问题（节选）

1. **整站白屏**：合并冲突修复时 router 丢失 `createRouter` 运行时导入（build 不查类型、运行时报错）——补回导入并连带修复两个页面的类型导入。
2. **“关联标的不存在”**：行情 store 异步化后 stocks 需 `bootstrapMarket()` 填充，评教页未触发导致提交失败——页面挂载时幂等触发加载。
3. **K 线图表崩溃**：KLineChart 按需化后残留 `echarts.init` 全量命名空间调用——改为已导入的 `init`，行情/详情/后台恢复。
4. **跨天任务断链与登录任务不可达成**：结算前置到每次写操作并自动达成当日登录任务。

## 五、协作与合流

多人并行分支 + 定期合流 main 是主要协作方式。期间经历多次合流冲突（页面重复拼接、EvaluationView 重构换版等），处理原则为“以集体主线为准、store/rules 等底层改动保留、页面级改动在合流时重放适配”；共享类型/mock/路由改动前先同步组长。全过程按天维护日报与 Reasonix 提示词记录，验证以「命令＋输出＋提交号」入库（见验证记录 V1–V8）。

## 六、总结与展望

本模块完成了从“规则散落”到“规则单一来源”、从“行为与任务脱钩”到“闭环联动”、从“构建绿即通过”到“类型/单测/端到端验证”的工程化收敛。后续方向：接入后端把 API 契约落地为真实调用、将规则库与后端对齐、在合流后的新评价架构上重跑交互回归并补充自动化用例。
