# 学林街之狼开发说明

## 项目概述

校园模拟投资、课程评价与任务激励平台的前端原型。项目中的教师股票、资产和收益均为虚构数据，不代表真实证券、教师收入或任何金融权益。

## 技术栈

- Vue 3 + TypeScript + Vite
- Vue Router + Pinia
- Element Plus + Lucide Vue
- ECharts

## 本地运行

### 环境要求

- Node.js 20 或更高版本
- npm（随 Node.js 安装）

### 安装和启动

```powershell
npm.cmd install
npm.cmd run dev
```

启动后访问终端显示的地址，默认是 `http://localhost:5173`。Windows PowerShell 如果受执行策略限制，请使用 `npm.cmd`，不要直接使用 `npm`。

### 构建检查

```powershell
npm.cmd run build
```

构建产物位于 `dist/`，该目录不提交到 Git。

## 当前功能

- 行情大厅、个股详情、K 线和评教趋势图
- 模拟交易、持仓、手续费、单标的仓位上限与 T+1 规则
- 到课签到、匿名评教、审核与评教奖励
- 任务奖励、排行榜、个人资产与校外权益展示
- 管理端的宏观因子调整、评教审核与收盘结算模拟

## 项目结构

```text
src/
  components/       可复用 UI 与图表组件
  mock/             原型阶段的初始模拟数据
  router/           路由定义和页面标题
  stores/           Pinia 业务状态与操作
  types/            跨模块 TypeScript 类型
  views/            页面级组件
  App.vue           应用布局和路由出口
  main.ts           应用入口
  style.css         全局样式
```

路由入口集中在 `src/router/index.ts`。业务数据目前保存在 Pinia store 中，刷新页面会恢复初始 mock 数据；接入后端时，应优先将 store 中的读写逻辑替换为 API 调用，保持页面组件只负责展示和交互。

## 开发约定

1. 从 `main` 拉取最新代码后创建功能分支，例如 `feat/trading-orders`、`fix/evaluation-form`。
2. 每个分支只处理一个清晰目标；提交前运行 `npm.cmd run build`。
3. 提交信息使用 `feat:`、`fix:`、`docs:`、`refactor:` 等前缀，例如 `feat: add order confirmation`。
4. 通过 Pull Request 合并到 `main`，至少由另一名组员检查后再合并。
5. 不提交 `node_modules/`、`dist/`、本地环境文件或访问密钥；新增配置时提供不含密钥的示例文件。

## 后续学习重点

1. **Vue 3 组件通信与组合式 API：** 理解 `ref`、`computed`、`watch`、`props`、`emit` 的适用边界，能将页面交互拆分为职责单一的组件。
2. **TypeScript 类型建模：** 优先掌握接口、联合类型、泛型和类型收窄；修改共享 `types/` 前先明确数据字段和状态流转，减少联调时的数据不一致。
3. **Pinia 与前端状态管理：** 梳理 store 中的状态、getter 和 action，重点理解跨页面数据联动、不可直接修改他人模块状态以及后续替换 API 层的方式。
4. **Vue Router 与权限边界：** 掌握嵌套路由、路由守卫、参数传递和 404 处理，为后续增加学生/管理员角色控制做好准备。
5. **前端测试与调试：** 学习为交易规则、奖励计算和审核状态编写单元测试；熟悉浏览器控制台、Vue Devtools、Network 面板和构建报错定位。
6. **Git 协作与项目管理：** 熟练使用分支、Pull Request、冲突处理、代码审查和语义化提交；用问题台账、验收清单和日报管理收尾阶段风险。
7. **答辩表达：** 按“问题背景→方案设计→核心流程→技术实现→验收结果→后续规划”组织讲述，清楚说明本项目采用虚拟积分和模拟数据，不提供真实金融服务。
