# 学林街之狼 最终答辩演示流程（单人版）

**演示人：张宏瑜（组长，24320230）**
**场景：D6 期末答辩，一人完成 8–10 分钟端到端演示**
**演示版本：Gitee `main`（`c420c15` 及之后），构建与 20/20 测试已验证（V11/V12）**

> 说明：团队版《演示脚本与分工.md》按五人分工编写；本单人版保留同一条产品主线（发现课程 → 查看评价 → 签到评教 → 模拟交易 → 任务奖励 → 榜单 → 管理审核），但全部由一人操作。页面真实状态来自 Mock 初始数据（见 `src/mock/initialData.ts`），以下标注“已知初始状态”的均可复现。

## 一、演示前准备（答辩前 30 分钟完成）

1. `git pull` 确认在 `main` 最新；`npm.cmd run build`、`npm.cmd run test` 各跑一次，确认全绿（对答案辩时的 V11/V12）。
2. `npm.cmd run dev` 启动本地服务；浏览器开两个标签页（主演示页 + 备用 `http://localhost:5173/market`）。
3. 全屏、关通知；浏览器缩放到 100%；不要开 DevTools 之外的插件。
4. 记住直达路由：`/market`、`/stock/1001`、`/courses`、`/evaluation`、`/trade`、`/profile`、`/tasks`、`/rankings`、`/admin`。
5. 先自己完整走一遍本流程 2 遍，**特别确认两件事**：
   - “我的课程”里“深度学习与大模型前沿”（明日课）点“签到”是否放行；若提示“未到签到时间”，当场改为只讲“已签课程的状态展示”，不反复尝试。
   - 管理端“模拟收盘结算”按钮点击后的页面变化是否可控；若觉得变化太大，现场只演示“评价审核”+“参数面板展示”，结算按钮口头带过。
6. 全程不要刷新页面（Mock 全内存，刷新即回初始态，但会丢掉“刚才提交的评价/买入”这条连贯剧情）。
7. 开场固定话术必须说：**本项目是校园教学评价与模拟投资激励平台的前端原型，所有“标的、行情、交易、资产”均为课堂演示用虚构数据与虚拟积分，不涉及真实证券交易，不构成任何投资建议。**

## 二、逐段流程（目标 8 分钟，含口播要点与操作）

### 段 1｜0:00–0:40 开场 + 行情大厅

- 操作：停留在 `/market`，指一下右上角品牌“学林街之狼”、学林综指、导航菜单、角色切换下拉。
- 口播（30 秒内）：
  1. “我们把一门门课程组织成**可比较的标的**：每门课有行情、评分、趋势、热度，学生像看行情一样快速找到值得上的课。”
  2. “整个平台围绕一条闭环：**发现课程 → 看真实口碑 → 签到评教 → 模拟投资激励 → 管理端审核与结算**。我今天一人把它完整走一遍。”
  3. 免责声明（见准备第 7 条，必须在开场说）。

### 段 2｜0:40–2:00 行情详情：K 线与评教趋势（钟森翔模块）

- 操作：
  1. 行情列表点“高数张”（代码 1001）进入 `/stock/1001`。
  2. 依次指：基础指标、K 线图（ECharts）、宏观因子、次日预测、近期评分与“评教趋势”小图。
  3. 把鼠标移到评分区，口播“下面这条评价会真的改变这里的评分聚合”。
- 口播要点：
  - “评价不再是一堆孤立文字，而是**可聚合、可比较的趋势数据**，这是本产品把课程做‘金融化表达’的核心。”
  - “K 线图走的是按需引入，不是全量 echarts（体积优化见收尾段）。”
- 已知初始状态：高数张持仓 60 股为“昨日买入、今日可卖”，详情页应能看到当前持仓行。

### 段 3｜2:00–3:10 我的课程 → 签到评教（周金淼/张善言模块，主线动作）

- 操作：
  1. 进 `/courses`：指 4 门课及状态列（已签/已评/待评）。
  2. 先点“数据结构与算法”（今日 10:00 已签未评）的“去评价”→ 直达 `/evaluation` 并按标的定位到赵梓涵老师。
  3. 在评教抽屉：打分 + 选 1–2 个标签 + 匿名评价一句（如“树与二叉树讲得清楚，板书工整”）→ 提交。
  4. 等成功提示出现，指余额/流水变化；回详情或评分榜看评分聚合微调。补一句口径：“**原型里新评教提交即公开、没有待审队列**；对异常内容的治理靠管理端降权/下架，第 7 段演示。”
- 口播要点：
  - “签到是评价的前置条件；这条评价提交后立即公开并计入评分（原型无待审队列），公开口径与降权/屏蔽由状态机单测固化。”
  - “评价完成会同时推进任务进度——一会儿到任务中心领取。”
- 可选加演（时间富余 20 秒）：若 cs-03“深度学习与大模型前沿”（明日课）允许签到，演示一次签到 + 到账提示；若不放行，一句话带过“签到窗口/前置关系由状态列体现”，不要反复点。
- 已知初始状态：cs-01 数据结构已签未评（本次提交即演示用评价）；cs-02 高数已签已评。

### 段 4｜3:10–4:20 模拟交易与个人资产（核心规则演示）

- 操作（按此顺序，先卖出后买入更顺）：
  1. 进 `/trade`，左侧选“高数张”；确认右侧显示“可卖 60 股”（昨日仓）。
  2. 方向切“卖出”，数量 10，下单 → 展示成功、手续费、可用资金增加、订单流水出现。
  3. 换“计网赵”（1005，80 股为今日买入 T+1 锁定）：方向“买入”再买 20 股 → 成功提示 + “当日买入不可卖出（T+1）”的提示/置灰表现，持仓更新。
  4. 进 `/profile`：指持仓市值、浮动收益、资产流水；**若时间够**：点“开通月卡”→ 回 `/trade` 再买一笔，展示手续费按 5 折计算（R14 规则）；时间不够则口播“月卡 5 折、30% 仓位风控、T+1 FIFO 都在 rules 纯函数里，20 条单测覆盖”。
- 口播要点：
  - “手续费、仓位风控、T+1 可卖批次全部收敛在 `rules.ts` 纯函数里，买卖前后统一走同一套计算，杜绝页面各自算账造成口径漂移。”
  - “今日买入的仓位置灰不可卖；昨日买入的高数张可以正常卖出，批次按 FIFO 扣减。”
- 已知初始状态：计网赵/AI 周为“今日买入已锁”，高数张“昨日买入可卖 60 股”；学生初始余额 10000。

### 段 5｜4:20–4:50 任务与奖励中心（张善言模块收尾）

- 操作：进 `/tasks`，指任务分类；领取刚才评价触发的已完成奖励 → 指余额/经验变化。
- 口播要点：“一次签到、一次评价、一次交易都会推进任务，把过程行为转成看得见的成长反馈；跨天结算用 localStorage 记录日期，只清每日任务。”

### 段 6｜4:50–5:40 排行榜 + 彩蛋

- 操作：
  1. 进 `/rankings`：依次指“杭电总资产”总榜、前三名“名人堂”独立卡片区、榜单切换（含龙虎榜等入口）。
  2. 回 `/market`（或直接在行情页搜索框）输入 `mj` + 回车 → 顶部播放团队彩蛋（约 5 秒即可，不必等播完，口播收住）。
- 口播要点：“排行榜的口径与个人资产来自同一 store 派生，名字/称号只是展示层表达；彩蛋是组员留下的公共交互，搜 `mj` 触发。”

### 段 7｜5:40–6:50 切管理员身份 → 风控后台审核与结算（王溢诚模块）

- 操作：
  1. **先在 `/market`（无角色限制的路由）再切身份**：点右上角角色下拉 → “管理员”。指导航栏随之变化：出现“风控后台”，学生/教师入口按权限收放。
  2. 进 `/admin`：在“评教审核与异常降权队列”中找到段 3 刚提交的那条数据结构评价（此时显示“正常计入”）→ 点“异常降权”→ 状态变“已降权”；可回评价展示区确认该条已对外下架（公开口径：仅“通过”保持公开）→ 回队列点“正常通过”恢复为公开。
  3. 展示宏观参数面板（初始资金、费率、月卡折扣、涨跌幅等）：“这些参数会写进下一轮结算规则。”**谨慎演示**“模拟收盘结算”——若你预演时发现变化太剧烈，就停在按钮上口播，不点击。
- 口播要点：
  - “四种身份（学生/校外/教师/管理员）由**路由守卫 + 菜单显隐 + store 功能矩阵**三层控制；教师是只读身份，管理员独占风控后台。”
  - “原型无待审队列、评价提交即公开；管理员对异常评价做**降权/屏蔽下架**，仅“通过”状态保持公开——这是‘事后治理’口径，回应‘评价如何防滥用’的问题。”
- 已知初始状态：段 3 新提交的评价立即公开并在队列显示“正常计入”（原型无待审队列）；若切身份后余额/流水被 `setRole` 重置为对应身份初始值，属预期（持仓不受影响），演示时不必惊讶。

### 段 8｜6:50–7:30 技术总结与收尾

- 不再操作，回到 `/market` 一句话定格。
- 口播（按实际讲，可裁剪）：
  1. 技术栈：Vue 3 + TypeScript + Vite + Vue Router + Pinia + Element Plus + ECharts；视图只做展示与交互，store 管跨页状态，规则抽纯函数可单测。
  2. 质量证据：`build` 通过（约 3963 modules）；规则单测 **20/20**（交易费率/月卡折扣/仓位风控/T+1 FIFO、任务领取、评价审核状态机）；首屏 JS 由 874 kB 优化到约 21 kB（echarts/element 按需 + vendor 拆分）。
  3. 边界与后续：当前为 Mock 数据原型；后续接 API 契约（契约文档已就位）、登录权限（前端四身份隔离已做）、持久化替换 Mock、加载/空态/失败重试完善。
  4. 再次免责声明，收尾：“我把课程口碑做成可以看的行情，把课堂行为做成有反馈的投资游戏——谢谢老师，欢迎提问。”

## 四、易错点与现场预案

| 风险点 | 处理 |
| --- | --- |
| 身份切换把余额/流水重置（`setRole` 行为） | 属预期；管理端演示放在流程末段，重置发生在审核前也不影响剧情 |
| 明日课程“签到”不放行 | 不纠缠，口播“签到前置与状态列”带过 |
| 管理端结算点击后变化过大 | 只展示参数面板 + 口播，不点结算 |
| 刚提交的评价找不到 | 提交即公开、直接进队列显示“正常计入”；按课程/老师定位即可，不必换初始评价重试 |
| 页面误刷新 | 从 `/market` 重来：行情 → 详情（可卖仓在）→ 课程直接“去评价”cs-01 → 交易卖出高数张 → 任务 → 排行 → 管理端审核初始评价；剧情仍成立 |
| 演示现场想展示代码/测试 | 不现场跑（避免环境波动），口播 V11/V12 并指向 `docs/24320230/验证记录.md` |

## 五、常见提问的口径

- **数据是真实的吗？** 当前是 Mock 原型，用于验证页面流程与状态联动；教师档案已整体脱敏（编号替代姓名，文件头声明为课堂演示数据）。
- **评价怎么防刷？** 签到前置 + 匿名提交；原型无待审队列、提交即公开，异常内容由管理员事后降权/下架（状态机与公开口径单测固化）；后续接入真实审核前置、身份与内容治理。
- **为什么用股票形式？** 一种信息组织与激励的产品表达，把课程口碑做成可比较的行情；底层是虚拟积分，无真实金融行为。
- **哪里最想继续做？** API 契约已就位，下一步是登录与权限服务化、持久化替换 Mock、加载/空态/重试与错误提示的系统化。
