记录 3：网络问题根因诊断与修复
================================================================

用户提示：
研究一下待做的内容，为什么网络有问题。

诊断结论：
- 现象：npm install 从官方源与 npmmirror 均 ECONNREFUSED，重试后 npm 自身崩溃（Exit handler never called!）。
- 根因：npm config 的 proxy / https-proxy 指向 http://127.0.0.1:7890（Clash/v2rayN 类代理默认端口），
  而该代理软件未运行，TCP 探测 7890 返回 ECONNREFUSED；Node fetch 直连 npmjs/gitee/npmmirror/baidu 全部 200，外网本身通畅。
- 结论：并非网络故障，而是 npm 流量全走了未运行的本地代理。

修复（用户选择“清掉代理配置并重装依赖”）：
- npm.cmd config delete proxy / https-proxy；
- npm.cmd install 12s 完成（68 packages）；
- npm.cmd run build 通过（33s），Day1+Day2 改动全部编译成功；
- 产物大 chunk 告警（KLineChart > 500kB）为既有 ECharts 全量引入问题，归 R16。

记录 5：机制讲解问答
================================================================

1) 为什么把金额/聚合公式抽到 src/rules.ts？
答复要点：规则与流程解耦、单一来源；纯函数可直接单测（本机无法起浏览器时仍能验证）；
命名即文档；为 R13/R14 预留复用边界。边界：仅“被多处消费或需验证的算法”才抽，UI 细节不抽。

2) 改签到奖励或聚合窗口要动几个文件？
答复要点（基于 grep 全量引用核对）：
- 改奖励金额：真·一处（rules.ts），store 发钱/提示文案/页面卡片/按钮/弹窗全部自动联动（15 处引用均读常量）；
  每日任务奖励是 initialData 独立配置，不受影响。
- 改聚合窗口：数据层一处自动（applyRatingAggregation 用 RATING_WINDOW）；
  但展示层仍有硬编码尾巴（RatingTrendChart 的“前第5讲”标签、slice(-5)、中性线 3.0，以及页面“近 5 讲”文案），
  属 Day3 组件增强范围，未收口前不能宣称“只动一处”。

3) 评教对股价的影响到底怎么算？
答复要点：
- 分两步：提交评教立即更新聚合分（last5AvgRating/recentRatings/rating），管理端“收盘结算”时因子才转为次日价格。
- 价格公式（market.ts calculateNextDayProjection）：
  Δ = E(评教) + F(资金) + M(宏观) + N(噪声)，E = α×(last5AvgRating−3)/2，截断 ±10%；
  次日价 = 现价×(1+Δ)。α=0.02、β=0.10、γ=0.005、σ=0.015。
- 示例：last5AvgRating=4.85 → E≈+1.85%（结算前还要叠加 F/M/N）。
- 单条评价仅占近 5 讲窗口 1/5，天然防刷分。
- 两点提醒：market.ts:61 内联公式与 rules.ts calcRatingFactorEarning 属两处拷贝（数值一致但 source 不同，收口需与
  钟森翔对齐，因 market.ts 是他的模块）；“次日生效”依赖管理员手动点结算且数据不持久化（刷新即复位）。
