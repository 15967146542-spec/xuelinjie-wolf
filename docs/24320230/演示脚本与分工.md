# 学林街之狼项目演示脚本与分工

**项目组长：张宏瑜**  
**建议时长：8-10 分钟**  
**演示版本：Gitee `main` 最新版本**

## 一、演示目标

用一条完整用户故事说明项目价值：学生先发现课程，再查看课程评价，完成模拟交易和课堂评价，获得任务奖励，最后由管理端完成审核和结算。演示重点是产品闭环和交互联动，不逐行讲代码。

演示开场必须说明：本项目是校园教学评价与模拟投资激励平台前端原型，所有“股票”“交易”“资产”均为虚构标的和虚拟积分，不涉及真实证券交易或投资建议。

## 二、上台分工

| 人员 | 上台职责 | 讲解重点 |
| --- | --- | --- |
| 张宏瑜（组长） | 开场、串场、技术架构、收尾答辩 | 项目背景、用户流程、Vue/Pinia 架构、项目边界与后续计划 |
| 钟森翔 | 行情与课程标的 | 行情大厅、筛选排序、标的详情、K 线和评教趋势 |
| 周金淼 | 模拟交易与资产 | 买入/卖出、持仓、手续费、T+1 和资产变化 |

张宏瑜负责控制时间和页面切换；每位成员只操作自己负责的模块，上一位讲完后由组长用一句话承接，避免多人同时操作。

## 三、演示前准备

1. 使用 Node.js 20 或更高版本，执行 `npm.cmd install` 和 `npm.cmd run build`，确认构建成功。
2. 启动 `npm.cmd run dev`，提前打开默认地址；演示开始前刷新一次，确保 Mock 数据处于初始状态。
3. 浏览器窗口全屏，关闭无关标签页和通知；准备 Chrome/Edge 两个浏览器窗口或一个本地备份页面。
4. 提前记住入口：`/market`、`/stock/1001`、`/courses`、`/trade`、`/evaluation`、`/tasks`、`/rankings`、`/profile`、`/admin`。
5. 不现场导入未知格式的课表文件；若演示导入功能，使用已准备好的 `.xlsx` 或 `.ics` 示例文件。
6. 演示前不要执行会改变依赖或源码的操作，避免临时安装、拉取或合并导致页面变化。

## 四、逐分钟演示流程

### 0:00-0:50 张宏瑜：开场与问题

讲解：传统课程评价信息分散、反馈滞后，学生难以快速了解课程，管理者也缺少直观的审核和趋势入口。我们用行情看板组织课程数据，用虚拟积分和任务提高参与感。

操作：停留在行情首页，展示项目名称和主导航。说明所有数据均为模拟数据。

### 0:50-2:00 钟森翔：行情与详情

操作：

1. 在行情大厅展示标的列表、涨跌、评分和热度。
2. 点击筛选或排序，说明用户可以快速找到关注课程。
3. 点击“高数张”或其他标的进入 `/stock/1001`。
4. 展示教师信息、K 线、近期评分和评教趋势。

讲解重点：课程评价不再是孤立文字，而是以趋势和聚合指标帮助用户比较课程。

### 2:00-3:30 周金淼：模拟交易与资产

操作：

1. 进入模拟交易页，选择一个标的。
2. 输入数量并完成一次买入，展示余额、持仓和订单变化。
3. 进入个人资产，展示持仓市值、浮动收益和资产流水。
4. 说明当日买入的持仓受 T+1 规则限制，手续费只用于模拟规则展示。

讲解重点：交易行为与资产状态由 Pinia store 联动，页面刷新后会恢复 Mock 初始状态。

### 3:30-5:30 张善言：我的课程、签到与评教

操作：

1. 进入 `/courses` 我的课程页面，展示课程安排和教师匹配。
2. 点击一门未签到课程的“签到”，说明签到奖励。
3. 点击“去评价”进入评教中心，提交评分、标签和匿名文字评价。
4. 展示评分聚合、评教趋势和评价奖励变化。

讲解重点：签到是评价前置条件；评价会更新虚拟标的评分，并推进对应任务进度。

### 5:30-7:00 王溢诚：任务与排行榜

操作：

1. 进入任务奖励页，展示日常任务、学期任务和成长任务。
2. 回到任务页领取已完成任务奖励。
3. 进入排行榜，展示资产、收益或参与成果的排名。

讲解重点：把一次签到和评教行为转化为可见的成长反馈，增强持续参与动力。

### 7:00-8:20 王溢诚：管理端

操作：

1. 进入管理端，展示评价审核列表和宏观参数。
2. 演示将一条评价改为通过、驳回或降权中的一种状态。
3. 展示模拟收盘结算入口，说明管理端用于教学演示和规则验证。

讲解重点：平台不仅服务学生，也提供面向教学管理者的审核和观察入口。

### 8:20-9:30 张宏瑜：技术总结与收尾

讲解：项目采用 Vue 3、TypeScript、Vite、Vue Router、Pinia、Element Plus 和 ECharts。页面组件负责展示和交互，store 负责跨页面状态，Mock 数据用于原型验证。后续将接入 API、登录权限、持久化和单元测试。

最后再次强调：本项目不提供真实金融服务，虚拟交易仅是教学互动形式。

## 五、现场操作注意事项

- 优先使用已经准备好的初始数据，不现场尝试未验证的边界输入。
- 先签到再评价，先买入再查看持仓；每一步都等页面反馈完成后再切页。
- 讲解人只说当前页面能证明的内容，不把后续规划说成已完成能力。
- 若某成员操作失败，组长直接跳到下一张准备好的页面，并用一句话说明该功能已在代码和构建中完成，避免现场反复点击。

## 六、故障预案

| 现场情况 | 处理方式 |
| --- | --- |
| 页面空白或加载失败 | 刷新页面；仍失败则切换备用浏览器窗口，直接访问已知路由 |
| 交易结果未变化 | 回到行情页重新选择标的，使用初始数据重新操作；不要连续重复点击 |
| 课表文件导入失败 | 跳过文件导入，展示已有课程列表和签到/评价流程，说明导入支持 `.xlsx`、`.xls`、`.ics` |
| 管理端操作异常 | 保留管理端页面展示审核列表和参数，将操作改为口头说明 |
| 网络不可用 | 使用本地开发服务和 Mock 数据；不要依赖外部 API |
| 构建或启动异常 | 使用演示前已打开的页面；演示后再处理依赖或环境问题 |

## 七、答辩可能提问

**问：为什么使用股票和交易的形式？**  
答：这是信息组织和互动激励的产品原型表达，底层使用虚拟标的和虚拟积分，用于帮助学生比较课程、参与评价；不涉及真实证券和收益。

**问：数据是否真实？**  
答：当前版本使用 Mock 数据，主要验证页面流程和状态联动。后续接入后端时需要完成授权、脱敏、审核和权限控制。

**问：如何保证评价不被滥用？**  
答：设计了匿名评价、审核、驳回和降权状态；后续还需要接入身份权限、内容审查和数据治理。

**问：项目最值得继续开发的部分是什么？**  
答：优先建立 API 契约和持久化层，再补充登录权限、交易与奖励规则测试，以及加载失败和空状态处理。
